修复官方 GitHub Desktop 升级后，用 Plus 打开时仓库列表被清空的问题；「打开方式」新增 Claude Code 与 Codex。

**仓库列表保护**

- 修复：官方升级到 3.6.10 后，Plus 会启动残留的旧版 3.6.7。原因是 `app-*` 目录按字符串排序，`app-3.6.7` 排在 `app-3.6.10` 前面。旧版打开新版迁移过的数据库时会把它清空，仓库列表随之变成 0。现在按版本号数字比较，跳过 Squirrel 标记为删除和未解压完整的目录；配置路径即使指向某个具体版本，也会改用最新版。
- 启动前读取四个版本来源：已安装目录、Windows 注册表、GitHub Desktop 自己的启动日志和 Plus 的启动记录。要启动的版本低于已运行过的最高版本时，Plus 拒绝启动并说明原因，不会先关闭你已打开的 GitHub Desktop。确需降级可运行 `gdp launch --allow-downgrade`。
- 官方更新正在安装时，Plus 会等待安装完成再启动，最多 2 分钟。
- 自动备份数据库（IndexedDB 与 Local Storage）到 `%APPDATA%\github-desktop-plus\desktop-backups`，时机包括：版本变化前；会话结束时如果官方已准备好新版本；平时每天最多一份。保留最近 5 份，以及最近 3 个版本各一份。
- 新增命令 `gdp backup list / create / restore`。恢复前会先把当前数据移到一边；备份由更新的版本写入时，默认拒绝恢复。`gdp detect` 会列出各版本来源，便于排查。

**打开方式**

- 新增「AI 助手」分组。自动检测可找到 Claude Code CLI、Codex CLI（在仓库目录打开新终端运行）、Codex 桌面版（以项目方式打开仓库）和 Claude 桌面版（通过 `claude://` 链接在 Code 中打开）。从文件右键打开时，AI 助手打开的是整个仓库。
- 程序路径现在也可以填写应用链接（如 `claude://…`），其中的 `%TARGET_PATH%` 会自动编码。
- 「折叠为子菜单」开启后，可在程序卡片上选择「单独显示」，让它直接留在右键菜单里。
- 修复：命令提示符、PowerShell、WSL 等控制台程序从右键菜单打开后窗口一闪即关。现在统一通过新的控制台窗口启动。路径中含有 `%` 的目录无法以这种方式打开，会给出提示。

已有用户需要在设置的「打开方式」中点一次「自动检测」，添加 Claude Code 与 Codex。

本版在 Windows 上验证了版本选择、注册表与日志读取、Claude Code CLI / Codex CLI / Codex 桌面版的检测，以及控制台程序启动；Claude 桌面版和 macOS 上的 AI 助手由单元测试覆盖，尚未实机验证。Claude 桌面版已在运行时，通过链接打开文件夹每次都会弹出信任确认，这是 Claude 桌面版目前的已知问题。
