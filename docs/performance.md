# 仓库切换与大型 diff 性能

GDP 在加载官方 `renderer.js` 时应用内存补丁，不修改 GitHub Desktop 的安装文件。
性能补丁独立于 Copilot 和汉化开关。源码特征不匹配或匹配不唯一时，该项保持官方实现，
日志会列出未支持的补丁；读取或转换失败时交回 Electron 加载原文件。

## 已处理的路径

- **大型 diff 行构造**：官方 `getModifiedRows` 为新增和删除行计算 token 后，反复使用
  `shift()` 消费 token 数组。改为索引读取，避免大块修改中反复搬移数组。
  保留统一视图与左右对照视图的完整内容、行号、行内高亮和选择所需的数据。
- **过时的仓库选择刷新**：在 `_selectRepositoryRefreshTasks` 开始处按仓库 ID 检查当前选择，
  并保留官方后续的实例检查。仓库恢复的异步检查结束时，如果用户已切换到另一仓库，就不再
  启动旧选择的 Git 刷新、issues、mentionables 和 PR 请求。同 ID 的恢复实例仍执行刷新。
- **汉化遍历**：在进入代码子树前剪枝，不再遍历每个高亮 token 后才判断是否跳过。
  用弱引用保留已翻译节点的恢复能力，避免长期持有已经卸载的仓库界面。
- **补丁加载**：异步读取 bundle，合并并发加载，并以路径、修改时间、大小和 Copilot 开关
  区分缓存；最多保留两份转换结果。

## 工作区 diff 与高亮内存

针对大量修改和反复切换仓库，另外加入两项独立的内存补丁：

- 切换仓库时释放非当前仓库的工作区 diff 原文与解析结果；保留仓库状态、提交草稿、
  勾选状态和部分行选择。工作区 diff 方法在开始及异步读取完成后检查当前仓库 ID，
  并用每次请求的标记阻止同文件的旧结果覆盖新结果，也覆盖切走再切回的情况，
  避免后台刷新或过时结果重新填充已经释放的 diff。重新打开仓库后，官方 status 刷新
  会重新加载工作区 diff。
- 高亮最多同时运行两个 worker、等待四个请求。队列满时，旧的等待请求以空语法高亮
  结果结束；diff 内容、行内增删标记和提交选择仍保持完整。完成后解除 worker 的事件
  回调，投递后解除主线程对输入请求的引用；worker 空闲 30 秒后终止，下一次按需创建。

此阶段仅淘汰工作区 diff。历史、stash 和 PR diff 的恢复路径不同，暂时保留；也不清空
包含提交/合并状态的整个仓库状态缓存。这些限制独立于窗口是否失焦，后续分级待机可以
进一步利用它们。

```powershell
node --expose-gc --import tsx scripts/checks/memory-retention.ts
```

隔离 V8 fixture 中，40 个仓库各保留 10,000 行 diff，释放非当前数据并在测试进程中显式
GC 后，39 个旧 diff 的弱引用目标均被回收，当前 diff 和草稿仍然存在。本机一次运行中，
fixture 增加的 JS 堆从约 112 MiB 降至 3 MiB。此结果只验证对象可回收，**不是用户所报
1–2 GB 的 Desktop 进程实测降幅**；应用总内存还包含当前仓库文件状态、DOM、worker、
原生分配和 Electron 进程等。

## 复现与验证

```powershell
pnpm run check
pnpm exec tsx scripts/checks/diff-performance.ts 'C:\path\to\GitHubDesktop\app-3.6.5\resources\app\renderer.js'
```

基准脚本从指定版本的真实 bundle 提取行构造函数，检查整个补丁后 bundle 的 JavaScript
语法，并比较优化前后完整行输出。对 1,000、10,000、50,000 行分别测量稠密和稀疏 token
数组，报告五次运行的中位数。token 生成器和行数据辅助函数使用相同的确定性替身，所以这里
测量的是**行与 token 数组组装**，不包含 Git、行内差异算法、布局和完整交互时间。

DOM 回归使用隔离的 DOM 环境，覆盖动态文本、语言热加载、上下文翻译、代码排除、节点在
界面与代码区之间移动，以及大型 diff 的遍历数量。它不是用户真实仓库上的交互测量。

2026-10-15 在 Windows / Node.js 22.22.2 上，两项源码补丁均匹配本机官方 3.6.4、3.6.5，
转换后的完整 bundle 语法检查通过。50,000 行稠密 token 修改块的组装中位数：

| 官方版本 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 3.6.4 | 5,567 ms | 57 ms |
| 3.6.5 | 4,898 ms | 48 ms |

两种视图的完整输出相等。这里的时间只对应上述组装阶段；小修改块的提升更小。
5,000 行 DOM fixture 中，优化后汉化遍历只访问外围 2 个节点，代码区属性子树查询为 0。

## 仍需区分的等待

用户本机日志曾记录 `git status --untracked-files=all` 耗时数秒。上述优化不会消除大型
工作区的磁盘扫描时间，也不启用有过期风险的 diff 结果缓存、不截断 diff、不修改 Git 配置。
如果使用新构建后仍出现长时间等待，需要针对具体仓库继续区分 Git 命令耗时和渲染线程长任务。

修改后需要重新构建并从新 GDP 启动，已经运行的 Desktop 不会自动替换其已加载的官方代码。
